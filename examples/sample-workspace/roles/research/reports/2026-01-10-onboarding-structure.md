# Domain report — onboarding structure

**Role:** Research  
**Date:** 2026-01-10  
**Question:** What should a new reader see before the full documentation map?  
**Project state examined:** `PROJECT.md` as of 2026-01-10  
**Authority:** RECOMMENDATION

## Executive result

Lead with the project promise and a small path selector. Place the complete repository map after the reader understands why the project exists and which path is relevant.

## Evidence

This sample intentionally omits real external citations. In a live report, each behavioral claim would link to a primary or authoritative source with an access date.

## Analysis

The project serves readers with different needs. A full file map is precise but forces every reader to interpret the entire system. A short selector lets each reader choose a path before encountering implementation detail.

## Recommendation

Use this order:

1. promise;
2. path selector;
3. compact lifecycle;
4. repository map;
5. limitations and provenance.

## Uncertainty

The report has not tested the structure with intended readers. Treat reader testing as follow-up evidence, not as completed validation.
