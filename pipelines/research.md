# Research pipeline

Turn an external knowledge question into a sourced, reusable project artifact.

## Use when

- a task depends on facts not present in the project;
- information may have changed;
- a decision needs sources rather than model recall;
- the result should survive the research chat;
- another role must be able to inspect how the conclusion was reached.

## 1. Define the question

Start with a bounded question, intended decision, scope, time boundary, and required depth. Use [Research brief](../templates/research-brief.md).

## 2. Define source priority

Prefer sources in this order unless the domain requires another hierarchy:

1. primary evidence and official documentation;
2. original research or direct records;
3. high-quality secondary analysis;
4. community reports for experience and discovery;
5. model inference, labeled explicitly.

Several pages repeating one statement do not automatically create independent confirmation. Trace the claim to its underlying source.

## 3. Search broadly, verify narrowly

Use broad search to discover terminology, disagreements, and candidate sources. Use the strongest relevant sources for final claims.

For time-sensitive facts, record an access date. For unstable claims, state the valid-as-of date in the report.

## 4. Separate evidence from inference

For each important conclusion, distinguish:

- what the source directly establishes;
- what is inferred by combining sources;
- what remains uncertain;
- what is a recommendation for this project.

## 5. Produce the report

The report leads with the answer, then provides evidence, limitations, and the decision it informs. Use [Research report](../templates/research-report.md).

## 6. Route the result

A research report informs a named recipient. It does not approve the resulting project decision unless that authority is explicitly granted.

## 7. Promote reusable knowledge

If the same domain question will recur, review the useful claims and promote them into an owned knowledge base. Then create or update a Domain Role contract.

One-off research should remain a report rather than creating a permanent role by default.
