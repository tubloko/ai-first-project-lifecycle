# Related work

This page is a dated landscape note, not a feature comparison or a claim of replacement. The lifecycle in this repository was built independently through one project’s evolution; many public systems have reached overlapping patterns.

**Landscape checked:** 2026-09-09

## GitHub Spec Kit

[Spec Kit](https://github.github.com/spec-kit/) uses durable artifacts across `Spec → Plan → Tasks → Implement`, supports many agent tools, and can host custom processes beyond its default flow.

## OpenSpec

[OpenSpec](https://github.com/Fission-AI/OpenSpec) provides a lightweight artifact-guided specification flow with proposal, application, verification, synchronization, and archive concepts.

## BMad Method

[BMad Method](https://github.com/bmad-code-org/BMAD-METHOD) uses a right-sized process, durable context, specialized perspectives, and reviewed implementation. Its process depth changes with the work.

## GSD

[GSD](https://github.com/open-gsd/gsd-core) focuses on context engineering, persistent planning artifacts, fresh agent contexts, orchestration, and verification.

## Agent OS

[Agent OS](https://github.com/buildermethods/agent-os) focuses on project standards and better specifications while allowing users to adopt only the parts that fit their workflow.

## Compound Engineering

[Compound Engineering](https://github.com/EveryInc/compound-engineering-plugin) connects brainstorming, planning, execution, review, and captured learning so later work can reuse earlier understanding.

## Ralph-style harnesses

Projects such as [ralph](https://github.com/yoshpy-dev/ralph) package project maps, skills, deterministic hooks, isolated execution, evidence-backed review, and optional autonomous loops.

## How to read the overlap

Common patterns do not make these projects interchangeable. They show recurring problems:

- context decays across long sessions;
- intent needs durable artifacts;
- planning and execution benefit from different context;
- verification must be explicit;
- autonomy needs boundaries.

This repository’s contribution is its particular working composition: four independently usable levels, role-owned knowledge and reports, visual artifact pipelines, explicit authority, and a failure-by-failure evolution record.
